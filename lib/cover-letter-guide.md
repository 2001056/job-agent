# 자기소개서 작성 가이드 (AI 작성 프로토콜)

> 어떤 지원자의 이력서와 채용 공고가 주어지더라도
> 일관된 품질의 자기소개서를 생성하기 위한 범용 작성 원칙입니다.

---

## 1. 채용공고 분석 프레임워크

자기소개서 작성 전 채용공고를 4가지 기준으로 분해합니다.

### 1-1. 포지션 핵심 정체성 파악
공고 제목과 주요업무 첫 줄을 보고 "이 회사가 진짜 원하는 사람"을 한 문장으로 정의합니다.
이 한 문장이 섹션 1의 도입부 방향을 결정합니다.

### 1-2. 자격요건 vs 우대사항 분리
- **자격요건**: 지원자가 충족하는지 이력서에서 직접 확인. 충족하면 구체적 사례로 뒷받침.
- **우대사항**: 해당하는 항목은 섹션 본문에 녹이고, 해당 안 되는 항목은 학습 의지로 대체.

### 1-3. 회사 도메인 이해
지원자의 어떤 경험이 이 도메인과 가장 직접적으로 연결되는지 찾습니다.
가장 관련성 높은 프로젝트 1~2개를 도입부에 배치합니다.

### 1-4. 회사 규모와 팀 문화 반영
- **소규모(50명 이하)**: "한 명이 넓은 범위를 커버"를 강조. 1인 개발 경험 전면 배치.
- **스타트업**: 속도, 0→1 경험, AI 도구 활용 강조.
- **핀테크/인프라**: 데이터 정합성, 동시성 제어, 성능 수치 강조.

---

## 2. 자기소개서 작성 원칙

### 2-1. 구조: 4개 섹션 고정

```
## 1. [도메인/역량 핵심 메시지] — 지원 직무와 가장 직결되는 경험
## 2. [기술적 깊이] — 구체적 문제 해결 사례
## 3. [폭과 인프라] — 넓은 역량 또는 운영 경험
## 4. [이 회사에서 하고 싶은 것] — 지원 동기 + 기여 선언
```

섹션 헤딩은 **질문이나 추상 선언이 아니라** 핵심 메시지 자체로 씁니다.
❌ "저는 성장하는 개발자입니다" → ✅ "결제 시스템에서 가장 중요한 것은 동시성 제어입니다"

### 2-2. 수치는 반드시 포함
모든 기술 섹션에는 이력서에 기재된 실제 수치를 최소 1개 이상 포함합니다.
수치가 없는 경우 정성적 결과(예: "데드락 제거", "배포 자동화")라도 명시합니다.

### 2-3. 사실 기반 작성 (거짓 금지)
지원자가 경험하지 않은 기술을 보유한 것처럼 쓰지 않습니다.
경험이 없는 우대사항은 다음 패턴으로 처리합니다:
> "X는 아직 직접 경험이 없지만, [유사 경험 / 학습 속도]을 바탕으로 빠르게 습득하겠습니다."

### 2-4. 연결 고리 명시
매 사례마다 **"이 경험이 이 회사/도메인에서 어떻게 쓰이는지"** 를 한 문장으로 명시합니다.
독자(채용담당자)가 연결을 스스로 추론하게 두지 않습니다.

### 2-5. 마지막 섹션(4번) 마무리 패턴
1. 회사/서비스에 대한 이해 1문장
2. 내가 이 도메인에서 풀고 싶은 문제 1문장
3. 보유 역량으로 기여할 준비 선언 1문장
4. 경험 부족한 부분이 있다면 학습 의지 선언 1문장

## 3. 반드시 피해야 할 AI티 패턴

아래 패턴이 포함되면 자기소개서가 AI가 쓴 것처럼 느껴집니다. 반드시 피하세요.

| 패턴 | 나쁜 예 | 처리법 |
|------|--------|--------|
| 연결어미 바로 뒤 쉼표 | "맡으며**,**" "써왔고**,**" | 쉼표 제거 또는 문장 분리 |
| ~것이 강점 | "~한 것이 저의 강점입니다" | 직설형: "~합니다" |
| 역량을 가지고 있습니다 | "경험을 갖고 있습니다" | "경험이 있습니다" |
| 할 수 있습니다 (약한 단언) | "기여할 수 있습니다" | 단언형: "기여하겠습니다" |
| ~다고 생각합니다 | "중요하다고 생각합니다" | "중요합니다" |
| ~습니다 4문장 이상 연속 | (단조로운 리듬) | 일부 문장을 동사형·명사형으로 변형 |

## 4. 좋은 문장 vs 나쁜 문장 예시

### 섹션 1 도입부

❌ **나쁜 예** (추상적, AI티 과다)
> 저는 개발에 대한 열정을 가지고 있으며, 끊임없이 성장하는 개발자가 되고 싶습니다.

✅ **좋은 예** (수치 포함, 도메인 직결)
> 결제 인프라의 핵심은 동시 요청이 몰렸을 때도 데이터가 정확히 하나의 결과만 만들어내는 데 있습니다. [프로젝트명]에서 초당 500건 동시 요청 테스트로 정원 초과 예약 발생률 0%를 검증했습니다.

### 기술 사례 마무리

❌ **나쁜 예** (A-7, A-10 패턴)
> 이러한 경험을 갖고 있기 때문에, 귀사에 기여할 수 있다고 생각합니다.

✅ **좋은 예** (연결 고리 명시, 단언형)
> [프로젝트]에서 쌓은 구조는 귀사 도메인의 [핵심 문제]와 같습니다. 기존 시스템에 바로 녹아들겠습니다.
